# fshake_skills

一套中文 Claude Code skill，实现「人定目标、AI 执行、多轮检查纠偏」的开发流程。

核心分工：**AI 负责「做」，人负责「定」。**

## 包含什么

| 目录 | 作用 |
|---|---|
| `vibe-coding/` | 总指挥。六阶段闭环流程，串起下面两个 skill，每个阶段设人工闸门 |
| `grilling/` | 需求追问。分轮次拷问计划，直到没有未决问题 |
| `review-and-fix-cycle/` | 复核循环。独立子代理查错 → 主代理逐条判断并修复 → 同一子代理再复核确认 |
| `.claude/skills/install-skills/` | 把上面三个装到全局。项目级 skill，自己不参与安装 |

`vibe-coding` 只能手动调用（`disable-model-invocation: true`）；另两个既能被自动调起，也能手动调。

## 安装

在 Claude Code 里输入 `/install-skills`，或直接说「装一下 skill」。

手动装也行——**先删后拷**：

```bash
REPO=/path/to/fshake_skills
for s in grilling review-and-fix-cycle vibe-coding; do
  rm -rf "$HOME/.claude/skills/$s"
  cp -r "$REPO/$s" "$HOME/.claude/skills/$s"
done
```

装完在会话里执行 `/reload-skills`（不必重启会话）。

> **为什么用复制而不是符号链接**：Node 扫描目录若用 `dirent.isDirectory()` 判断，符号链接目录返回 `false`，会被**静默跳过**——不报错，skill 直接消失。代价是仓库与安装位置分离，**每次改完仓库都要重装一遍**。

## 用法

```
/vibe-coding 给配置页加一个 CSV 批量导入
```

也可以单独用：

- `/grilling` —— 只想被追问、还没打算动手
- `/review-and-fix-cycle` —— 已经改完一批文件，只想复核

## 流程

| 阶段 | 做什么 | 闸门 |
|---|---|---|
| 一 · 需求构思与深度规划 | AI 产出 11 项开发计划；`grilling` 分轮追问 | **G1** 人确认计划 |
| 二 · AI 执行开发 | 一次性写完本轮全部改动 + 同步写单测 | **G2** 人确认开发完成 |
| 三 · AI 自动复核 | 独立子代理查错，循环至收敛 | **G3** |
| 四 · 人工审查与系统验收（可选） | 人看代码、人真跑系统 | **G4** / **G5** |
| 五 · 最终验证（可选） | 全量单测 / 端到端 / 发布测试，任选 | **G6** |
| 六 · 提交代码 | 自查暂存范围、起草提交信息 | **G7** 人授权提交 |

阶段四、五**可以跳过**，但只有人能提——AI 不许建议跳过。跳过了什么，必须写进提交信息（`未人工测试` / `未做最终验证`）。

## 硬规则

| 规则 | 说明 |
|---|---|
| **四件事逐次获批** | `git commit` / `git push` / 跑**全量**单元测试 / 删除数据库。每次单独问，**上次同意不算这次**（跑单个测试文件不受限） |
| **闸门只能由人打开** | 静默 ≠ 同意。模糊回复（「嗯」「哦」「再看看」）视为未确认 |
| **不改变目标** | 实现细节可自主决定，需求/范围/技术选型/对外接口必须停下来问人 |
| **交付版本由子代理确认** | 最后一轮必须是子代理的确认回执，不是主代理自述「已修复」。确认之后再改一个字符，确认作废 |

## 改完记得重装

改了仓库里的任何 skill 文件，都要**重跑安装**再 `/reload-skills`，否则改的是仓库、生效的是旧副本。
