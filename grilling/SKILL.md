# 拷问

就计划、决策或构想持续追问，直到达成**共识**。把它映射成一棵**设计树**：每个决策分叉出挂在它下面的子决策。

> 用户可以直接说「拷问我这个方案」启动；`vibe-coding` 也会在计划阶段自动调用。

## 分轮次推进

**可问集** ＝前置条件已确定、**现在就能问**（无需猜测未听到的答案）的决策集合。一轮问完整个可问集，逐条编号并给出推荐答案，然后**等用户回答**，再进下一轮。

问题格式：

```
❓ **Q1** - **<问题标题>**: <问题正文，可以有多段，可以包含多个选项>

➡️ <你的推荐答案>
```

> 上述格式是线格式契约，**原样保留**（含表情符号、`➡️`、`Q1`、占位符形态）。用户要靠它在多轮对话里快速扫读。

用户每轮的回答都会重塑这棵树：已确定的决策把可问集向外推进，解锁依赖它们的问题；重算可问集，问下一轮。**某问题的答案依赖于本轮另一个仍未回答的问题时，它属于更晚的轮次。**

## 事实与决策的分工

**找事实是你的工作，永远不是用户的。** 可问集里的问题需要环境中的事实（文件系统、工具等）时，派子代理去查；不要问用户任何你自己能查到的东西。

**探查没收回，本轮就不发问。** 只要本轮派出过探查且尚未全部回报，就**等它们全部结束、重算可问集之后再统一发问**——哪怕有些问题看起来不依赖探查结果。探查结果会**改写问题本身**：可能让某个问题不必问了，也可能炸出新的分叉；先发一半＝把一次拷问拆成两轮，用户白答一遍。

**探查期间要出声。** 派子代理时先说一句在查什么、为什么这轮要等。

**探查失败也算收回，不许再等。** 子代理报错、超时、或只丢回一句含糊结论（「大概是……」）都算没查成。**既不要继续等，也不要自己猜个答案填上**——如实标成「未查明」，转成一条交用户裁决的问题，跟着本轮一起发出去。

等待的出口只有两个：**全部查明**，或**已确认查不到**。没有第三个。

**决策是用户的**：探查全部收回、可问集重算完毕后，逐条交给用户，然后等。

## 结束条件

可问集为空时结束：设计树的每个分支都走过了，没有任何东西被静默假设。

**在用户确认你们已达成共识之前，不要据此行动。**
