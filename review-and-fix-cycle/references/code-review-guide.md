# 代码审查指南

审查工作区未提交的修改（`git diff HEAD`），发现 BUG、功能异常、安全漏洞和代码质量问题。

**这份指南是 `review-and-fix-cycle` 第一阶段（子代理复核）的审查标准。** 子代理应逐项按此执行。

## 流程

### 1. 收集差异

运行 `git diff HEAD` 获取所有未提交修改的 diff。如有新文件，一并读取。

### 2. 分析角度

并行从以下角度发现问题：

| # | 角度 | 说明 |
|---|------|------|
| A | 逐行扫描 | 反转条件、空值解引用、缺 `await`、假零值检查、复制粘贴错变量、catch 吞错误、未转义正则元字符 |
| B | 删除行为审计 | 每行被删代码维护了什么约束？新代码中是否重新建立？找不到即为候选 |
| C | 跨文件追踪 | 被修改函数的调用者是否被破坏？被调用方是否安全？ |
| D | 复用 | 新代码是否重复实现了已有工具函数？ |
| E | 简化 | 冗余衍生状态、复制粘贴稍作修改、深层嵌套、遗留死代码 |
| F | 效率 | 冗余计算、重复 I/O、可并行却串行、启动路径阻塞 |
| G | 深度 | 特例堆积在通用基础设施上？改为泛化底层机制而非加特例 |
| H | 约定 | 检查是否违反 CLAUDE.md 或项目文档中的明确规则 |

### 3. 验证

每个候选问题交给一个验证者，判断：

- **已确认** — 确实存在
- **可能成立** — 在合理的运行时状态下可达（不因其"推测性"而驳回）
- **已排除** — 事实错误、不可能到达、本次 diff 已处理

保留已确认和可能成立，丢弃已排除。**可能成立为默认判决。**

### 4. 报告

输出最多 10 条，按严重度排序。每条包含文件路径、行号、一句话描述、具体故障场景。

分类：

| 分类 | 说明 |
|------|------|
| 🔴 功能 Bug | 影响用户可见的正确行为 |
| ⚠️ 功能风险 | 特定条件可能触发的问题 |
| 🔧 代码质量 | 死代码、未使用导入、类型安全 |
| 🔒 安全漏洞 | XSS、注入、权限泄露 |

## 常见检查项

> 以下为**示例项目**（Vue + TypeScript 前端）沉淀的具体检查项。换个技术栈请按同样的粒度替换成本项目的高频出错点，**不要把这一节当成通用清单**。

### Vue 模板
- `v-if` / `v-show` / `v-else` 条件是否与原逻辑等价
- 插槽内容在所有状态下是否正确可见
- 事件监听是否完整迁移
- loading/error 状态显示是否一致
- `v-for` 的 `:key` 是否唯一且稳定

### 响应式状态
- 删除的 watch 是否有替代方案
- `ref`/`reactive` 变量是否定义但不再使用
- `withDefaults` + `in` 运算符陷阱：default 值使 prop 始终存在，区分未传应改用 `prop !== undefined` 且不从 `withDefaults` 设默认值

### 导入
- 组件重构后是否有未使用的 import 残留
- 废弃的 icon/组件导入是否清理

### 类型
- `any` 是否能替换为具体类型
- 新接口是否在 `types/index.ts` 中正确定义并加入联合类型

### CSS
- 删除的样式类是否有关联 DOM 元素也一并删除
- 布局关键类（如 `flex: 1` 占位）是否被误删

### 功能回归
- 异步数据到达后 UI 是否正确更新
- 自定义状态文字（statusText）是否丢失
- 空状态/错误状态的守卫条件是否保留
- 用户交互（点击展开收起、切换等）是否正常

## 安全红线

- 用户输入是否经过消毒（DOMPurify、参数化查询等）
- Markdown/HTML 渲染是否 sanitize
- 后端 SQL 是否参数化
- 文件路径拼接是否存在路径遍历风险
- 鉴权/权限检查是否被绕过
