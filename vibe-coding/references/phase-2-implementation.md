# 阶段二 · 完整开发

**目标**：按确认后的计划完成本轮全部开发，并同步交付单元测试。
**入口**：闸门1 已确认。**出口**：人确认开发完成（闸门2）。

> 📌 本阶段**每一次回复**的末尾都要带阶段脚注（格式与措辞见 `SKILL.md` §0.1）。开发进行中通常是「继续本阶段 —— 已 x/N，无需你操作」。
> 📌 本阶段**默认开启自动续行**（goal 模式）——规则见 `goal-continuation.md`，本阶段映射见 §3.2。
> 🚫 **前提：平台有 goal 工具**（不确定按没有办）——没有就**忽略整份 `goal-continuation.md`**，一轮一停，脚注不写「无需你操作」。**goal 只服务本阶段**，到闸门2 必须 `complete` 收口。

> 📖 **开工前先读 `coding-conventions.md`**（与本文件同目录）：注释与文案用什么语言、emoji、界面文字的文风、改动边界在哪——别处没写的约定都在那里。

> AI 可以自主执行，但不能自主改变目标。

## 1. 「一次性」的确切含义

计划确认后，**在本轮内做完本轮计划内的全部改动**（「本轮」＝这一整批，可跨多次回复；别把整批硬塞进一次回复里——那正是 `goal-continuation.md` §8 要防的失效点）。

| 是 | 不是 |
|---|---|
| 改完计划列出的所有文件 | 拆成多轮「先做一半给你看看」 |
| 补全所有关联模块的适配 | 留下「关联模块下次再改」 |
| 同步写完单元测试 | 先写代码，「测试回头补」 |
| 自己先把能跑的部分跑通 | 交一堆半成品等人发现问题 |

**不留 TODO、不留「下次再」、不留注释掉的旧代码。**

**用户说「开始」之后不要停下来等回复。** 一路做到「可以请他拍板去阶段三」的程度——计划项全部完成、单测写完、自测通过——才停在闸门2。

> **术语**：「本轮」「回合」的定义见 `goal-continuation.md` §8；凡涉及工具授权、续行、截断、驱动排期，一律说「回合」。

会打断这条「一路做下去」的**只有四件事**，除此之外任何一次停顿都是违规：

1. 人主动叫停（§3 四步协议）；
2. §3 偏差分级里判定要停的偏差（**目标偏离**、**实现偏差**）；
3. §3 偏差分级里判定要停的问题——**唯一合法方式是把问题提给人**（`ask_user_question` 可用时必须用它，问法见 `goal-continuation.md` §6），不是留个问句就结束回合；
4. **续行已停或掉线，需要用户开口才能恢复**——状态分类与各自的话术**一律以 `goal-continuation.md` §7 表为准**（`paused` / `active 但 disarmed` / `round-limit` 恢复方式各不相同，别混用）。说清当前状态与恢复方式，然后停下等，是合法收尾，不算违规。

> 偏差该怎么停、停在哪个动作，**一律以 §3 的表为唯一判据**，本节不另立规则：目标偏离 = 停下问，实现偏差 = 停下说明差异请人裁决，**两者都不许自作主张地继续**。

**途中的播报是让他随时能叫停，不是请他逐项点头。** 播报完立刻做下一项，**并且不要在播报后以「等你回复」的姿态收尾**——鼓励人打「继续」来推动你，等于把本阶段的工作量转嫁给他。

> ⚠️ 一段话里有多个动作时，把它做完再收尾。**「先报告一项，等他说继续再做下一项」是最常见的违规形态**，它看起来像播报，实际是逐项征求同意。

「一次性」不等于「不能中断」——环节6 的叫停权**永远有效**、随时可触发。

### 1.1 委托子代理执行时的边界（仅当用户点名要求时）

**默认是主代理自己写。** 只有用户明确要求（如「为了省上下文，本次开发交给子代理」）才委托；无论谁敲键盘，这批代码的成败都记在主代理头上。

委托**不放宽本阶段的任何一条规则**——一次性做完、同步写单测、偏差分级、闸门2 报告，一条都不变。它只是换了执行体，所以额外守这些边界：

- **先切分，再派发**：按**文件 / 模块**切，**同一个文件只允许有一个写者**。多个子代理并发改同一棵树是最容易踩的坑——各改各的都能编译，合起来往往直接编译不过（实践教训：4 个子代理改同一个 crate，最后只能整体作废、由主代理重写）。
- ⚠️ **开了自动续行时，委托期间必须先停掉它**：主代理等子代理交回时是 idle，续行会立刻排新回合，让主代理在子代理还在写的时候「接着做」——正好违反上一条。用户点名委托的那个回合里 `update_goal(action: pause)`，本轮收完再按需 `resume`（见 `goal-continuation.md` §7）。
- **子代理只做「按计划实现 + 写自己那部分的单测」。** **合并、编译、跑测试、偏差分级、闸门2 报告一律由主代理独占**：子代理不得自行跑全量测试（`SKILL.md` §1 禁令 3）、不得提交、不得与别的 agent 抢构建产物锁（见 `coding-conventions.md` §5）。
- **派发前先留存档点**（补丁 / 临时分支 / `git stash`）。子代理交回不可编译或偏离计划的树时**整体回退，不逐个缝补**——缝补的代价通常高过自己重写。
- **委派 ≠ 免责**：主代理必须自己验（编译、单测、逐文件 diff 自查）。**「子代理说做完了」不算交付**，不许拿它当闸门2 的证据。
- **待裁决项由主代理代问**：子代理调不了 `ask_user_question`（见 `goal-continuation.md` §6），**派发时**就要求它把问题写进最终报告。
- **闸门2 报告写明分工**：哪几项由子代理写、哪几项主代理自己写——人有权知道这批代码是谁敲的。

## 2. 同步编写单元测试（环节5）

测试不是验证「能不能跑」，而是**覆盖尽可能广、测试尽可能深**。必须覆盖 7 类维度：

| # | 维度 | 正例 | 反例 |
|---|---|---|---|
| 1 | **正常流程** | 输入合法数据 → 返回预期结果 | 只测了正常路径的中间状态，没测最终落库/渲染结果 |
| 2 | **异常流程** | 网络失败 → 返回明确的错误 + 不破坏既有状态 | `expect(() => fn()).not.toThrow()`——只证明不崩，没证明行为正确 |
| 3 | **边界条件** | 空数组 / 零 / 最大值 / 超长字符串 / 首次运行 | 只测 `[1,2,3]`，不测 `[]` 和 `[1]` |
| 4 | **极端输入** | 超大数据量 / 并发提交 / 非法字符 / SQL 与 HTML 注入串 | 只测「正常字符」，注入串没试过 |
| 5 | **核心业务逻辑** | 直接断言业务规则（折扣计算、状态流转、权限判定） | 只测了外层包装，核心分支没进 |
| 6 | **模块间交互** | A 调用 B 时，B 失败/超时/返回空时 A 的表现 | 模拟掉 B 后只测 A 的成功路径 |
| 7 | **回归风险点** | 本次改动**可能影响到的既有行为**，各补一条守卫测试 | 只测新功能，不管旧功能会不会被改坏 |

### 落点约定

- 测试文件遵循**本项目既有约定**（此处填：`<测试目录 / 命名规则 / 运行命令>`）。
- 新增测试与被测代码**同一次提交**，不分开。
- 每条测试的名字要说清「在什么情况下期望什么」，不要叫 `test1`。

## 3. 人工监督与纠偏（环节6）

人全程观察，持有**常驻叫停权**。发现偏离时执行四步协议：

```
1 立即叫停  →  2 指出偏差  →  3 纠正方向  →  4 继续执行
```

**你的义务**：听到叫停，**把手上的动作收在当前位置，不再往下扩展**——已经开始写的这一处可以写完（免得留半个坏文件），但**不新开文件、不新开计划项**。说一句你理解的偏差和纠正后的方向，然后继续。

### 偏差分级

**判据只有一条：人已拍板的「做什么」有没有变。** 与「文件在不在计划清单里」无关。

| 偏差类型 | 判据 | 例子 | 处理 |
|---|---|---|---|
| **目标偏离** | 改变了人已拍板的「做什么」 | 加了计划外的功能；换了技术方案；改了数据结构或对外行为 | **立即停**，报告闸门1 重确认 |
| **计划补漏** | 计划自身漏项或矛盾，不补则跑不通；「做什么」没变 | 依赖表漏列（如 `tsconfig` 要 `@types/node` 但依赖表没写）；`npm install` 生成的 lock 文件；计划漏列的测试文件；让计划里的命令能跑通所需的最小改动 | **记录，继续执行**，在闸门2 逐条列出。**命中下面白名单、且未越出「不改对外行为」红线的，一律按本行走，不必问** |
| **实现偏差** | 做法与计划描述不符但目标一致 | 换了等价写法、调整内部函数划分 | 停，说明差异，请人裁决 |
| **风格偏差** | 命名、代码组织、注释密度 | — | **记录，继续执行**，在闸门2 一并报告 |

> 分不清时按目标偏离处理——**但「停下来问」指的是把问题提给人（`ask_user_question`，见 `goal-continuation.md` §6），不是留个问句就结束回合。**

### 计划补漏白名单（命中即记录 + 继续，不停）

下列情形**一律按计划补漏处理**，不必停、不必问：

- 计划漏列的依赖、生成物、lock 文件；
- 计划未列的测试文件——单测是本阶段必交项，写它永远不算加功能；
- 让计划列出的命令能真正跑通所需的最小改动（配置、类型声明、路径修正）；
- 被改动的接口**签名与对外行为都没变**，只是消费方跟着内部实现调整（改名、搬位置、换等价写法）。

**红线（越出白名单就要停）**：任何改动一旦**改变了对外行为**——数据结构、接口签名、既有输出格式、权限判定——就不再是补漏，**按目标偏离停下来问**。

> 最容易踩线的是「关联模块适配」：**适配本身是补漏**（计划本就要求补全），**但如果适配过程中需要改接口签名或数据结构才跑得通，那就已经越线**——那种情况停下问，不要为了跑通而顺手扩接口。

## 3.2 自动续行

**本阶段默认开启**（入口闸门1，出口闸门2）——**除非用户明说不**。规则见 [goal-continuation.md](goal-continuation.md)：那份是唯一真源，装备、收口、卡死、断线、截断全在里面，**此处不复述**。

本阶段只需记住两点：**闸门1 确认后的第一个动作是 `create_goal`**（前提是先判断用户有没有拒绝，且平台有该工具——见本文件开头 🚫）；**停在闸门2 时先 `update_goal(complete)` 再出闸门块**——注意先跑完 `git status`/`git diff` 收数据，收口后就不能再调工具了。

## 4. 报告节奏

**每完成一个计划项就播报一行**并更新任务列表：

````
【阶段2：开发】已完成 3/7：数据结构定义、模块 A、模块 A 单测
下一项：模块 B

> **当前：阶段2 · 开发**
>
> **建议：继续本阶段** —— 还剩 4/7 项（模块 B、C、D 及其单测），无需你操作；发现问题随时叫停我。
````

不要闷头做完再一次性汇报——那等于放弃环节6。若一轮回复内确实来不及中途播报就做完了，**闸门2 报告必须逐项列出**完成情况，不能只写个总数——播报的目的是让人随时能叫停，闸门2 报告就是一轮做完时的那个出口。

> 播报之后**立刻做下一项**。不要问「要我继续吗」，也不要用「等你回复」的措辞收尾——那会把「打继续」变成流程的一部分，正是本阶段要消灭的。

---

🛑 **闸门2：开发完成移交**

停在何处：计划内全部改动完成、单测写完、自测通过。**此刻不得启动复核。**

**本闸门那个回合的内部顺序（见 `goal-continuation.md` §4）**：① 先跑完 `git status` / `git diff` 采集下面要填的数据 → ② `update_goal(action: complete)` 收口（用户拒用过 goal 模式的跳过）→ ③ 输出本闸门块与脚注。**①必须在②之前**：收口后命令你不要再调工具，那时只剩记忆可填。**收口又必须在③之前**：否则人还在看报告，驱动会再排一个回合。

本轮输出（≤10 行要点 + 逐条待确认项）：

```
计划项完成：7/7（逐条勾）
改动文件：<N 个，列关键几个>
计划外改动：<计划没写但实际新增/修改的文件，逐条标注属「计划补漏」还是「目标偏离」及原因；无则写「无」>
新增测试：<N 条，覆盖维度>
风格偏差记录：<执行阶段自主决定的事项，如有>
待确认项：
  1. <自测中发现但未处理的问题，如果有>
```

向人提问（照抄）：

> 本轮开发已按计划一次性完成，单元测试已同步交付。请确认后我将进入阶段三（独立子代理交叉复核）。

未确认前禁止：
- 不得派子代理启动复核
- 不得进入阶段三
- 不得「先自己审一遍等你回」
- 模糊回复视为**未确认**，必须再问一次

> **当前：阶段2 · 开发**
>
> **建议：可进入阶段 3** —— 计划项已全部完成、单测已交付，回「确认」我就派独立子代理交叉复核。
