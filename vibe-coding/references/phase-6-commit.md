# 阶段六 · 提交代码

**目标**：把本次完整修改正式提交到 Git 仓库。
**入口**：G6 通过，**或 G3 / G5 后用户要求直通**（跳过阶段四/五，须注明跳过项）。**出口**：提交完成 + 交付小结（G7）。

> 📌 本阶段**每一次回复**的末尾都要带阶段脚注（格式与措辞见 `SKILL.md` §0.1）。停在 G7 时是「等你授权提交」；交付小结之后是流程终点，写「已完成」。

---

## 1. 最终确认清单

逐条勾，**对照阶段一的计划**：

- [ ] 计划的每一项都已实现（未实现的**必须显式列出**）
- [ ] 修改范围与计划一致（没多改、没少改计划外的文件）
- [ ] 单元测试全绿，无回归
- [ ] 本轮选定的最终验证方式通过（或已确认跳过，并已在提交信息注明）
- [ ] 阶段三判定「不属实」的问题都已写明理由
- [ ] 阶段四 G4 / G5 均已通过（若跳过则已在提交信息注明）
- [ ] 遗留风险已列出

---

## 2. 提交前自查

**提交前必须跑这两条**（本项目此处填实际命令，通常就是这两条）：

```bash
git status              # 看哪些文件被改动/新增/删除
git diff --staged       # 逐行看即将提交的内容
```

### 不该提交的东西

- 本地配置（`.env`、`settings.local.*`、IDE 配置）
- 构建产物（`dist/`、`build/`、`node_modules/`）
- **密钥、token、证书**（提交即泄露，且会留在 git 历史里）
- 临时调试代码（`console.log`、写死的测试数据、注释掉的大段代码）
- 被删除但未 `git rm` 的文件（会以「已删除但未暂存」的状态残留）

**暂存范围**：只 `git add` 本次改动涉及的文件，不要 `git add -A` 一把梭。

**提交粒度**：**默认单一提交**——本次任务的全部改动合成**一个** commit，不要把「写代码」「补测试」「修复复核问题」拆成一串。**仅在用户明确要求拆分时才拆。**

### 分支

- 若当前在默认分支（`main` / `master`），**先建分支**再提交。
- 分支名说清做了什么，如 `feat/config-batch-import`。

---

## 3. 提交信息模板

```
<类型>: <一句话说清做了什么>

<可选正文：为什么这么做、有什么取舍、未覆盖的部分>

跳过项：<本次未走的环节；无则整行省略>

Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
```

类型：`feat` / `fix` / `refactor` / `perf` / `test` / `docs` / `chore`

### 跳过项必须写进提交信息

只要本次**跳过了阶段四或阶段五**，正文里**必须**列明：

| 跳过的 | 必须写 |
|---|---|
| 阶段四（人工审查 / 系统验收） | `未人工测试` |
| 阶段五（最终验证） | `未做最终验证` |
| 两者都跳 | 两条都写 |

**不得只写「已完成」而不提跳过项**——那是静默收尾。人没验过，提交历史里就得看得见。

**要点**：标题 ≤50 字，说清**做了什么**而不是「update files」；有测试因过时被更新的，在正文说明是哪一条、为什么；有未覆盖项的，在正文列出。

**仅在人明确授权后执行提交。** 提交是外向且难以撤销的动作。

---

🛑 **闸门 G7 — 提交授权**

停在何处：自查完成、提交信息已起草。**此刻不得 `git commit`。**

本轮输出（≤10 行要点 + 逐条待确认项）：

```
【阶段 6 · 环节 ⑭】
最终确认清单：<逐条勾，见 §1>
暂存范围：<N 个文件>
拟提交信息：
  <标题>
  <正文要点>
未覆盖项：<列出，若无则写「无」>
遗留风险：<列出，若无则写「无」>
```

向人提问（照抄）：

> 全部环节已通过，提交信息见上。确认授权提交请回复「提交」，我将执行 git commit。

未确认前禁止：
- 不得 `git commit`
- 不得 `git push`（**提交授权 ≠ 推送授权**，推送要单独再问一次）
- 不得「先提交到本地分支等你回」

---
🧭 **当前：阶段 6 · 提交代码** ｜ 环节 ⑭ ｜ G7 待授权
🚧 此刻不做：`git commit` / `git push`
💡 **建议：等你授权提交** —— 自查与提交信息见上，回「提交」我就执行 `git commit`（推送我会另问一次）。
---

---

## 4. 交付小结

提交完成后输出（**这是流程的收尾，不是可选步骤**）：

```markdown
## 交付小结

**改动**：<对照计划逐条列出，标 ✅/❌>

**验证**：
- 本轮方式：<A 全量单测 / B 端到端 / C 发布测试，可多选；跳过则写「未做最终验证」>
- 结果：<A：新增 N 条 / 原有 M 条 / 全绿；B：接口 N 个全通过；C：各项通过>

**未覆盖项**：<计划里有但没做的，逐条列出并说明原因；无则写「无」>

**跳过项**：<本次跳过的环节，须与提交信息里的注明一致；无则写「无」>

**遗留风险**：<已知但本次不处理的；无则写「无」>

**提交**：<分支名> <commit hash>
```

**未达成的计划项必须显式列出，不得静默收尾。**

小结之后，整条回复以阶段脚注收尾（`SKILL.md` §0.1 的最后一种建议）：

```
---
🧭 **当前：阶段 6 · 提交代码** ｜ 环节 ⑭ ｜ G7 已通过
🚧 此刻不做：`git push`（要推的话请明确说，我会单独确认一次）
💡 **建议：流程已完成** —— 已提交到 <分支名> <commit hash>，本轮流程结束。后续要推送或做别的改动，直接说。
---
```
